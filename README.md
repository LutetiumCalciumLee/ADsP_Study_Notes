# ADsP II. Data Analysis Planning

## 1. Types of Analysis Tasks
### (1) Understanding Analysis Planning
Analysis planning consists of:
- **What** → Objectives and targets
- **How** → Methods and procedures
### (2) Types of Analysis Tasks
Analysis tasks can be classified according to whether the **target (What)** and **method (How)** are known.
| Method / Target | Known | Unknown |
|---|---|---|
| **Known** | Optimization | Insight |
| **Unknown** | Solution | Discovery |
- If the **target is known** → **Optimization (OS)**
- If the **target is unknown** → **Insight Discovery (ID)**


---

## 2. Objectives and Considerations of Analysis Planning
### (1) Analysis Planning by Objective
- **Analysis Task**
  - Focuses on solving a problem.
- **Analysis Master Plan**
  - Focuses on defining the problem.
### (2) Considerations in Analysis Planning
1. **Available Data**
2. **Appropriate Use Cases**
3. **Constraints**


---

## 3. Software Development Methodologies
### (1) Waterfall Model
- **Top-down** approach
- Uses feedback between stages.
### (2) Spiral Model
- **Bottom-up** approach
- Requires management of repeated iterations.
### (3) Prototyping Model
- **Bottom-up** approach
- Compensates for the limitations of the Waterfall Model.


---

## 4. KDD Analysis Methodology
### (1) Overview of the Analysis Methodology
The methodology connects **tacit knowledge**, **explicit knowledge**, and analytical methods.
- **Tacit Knowledge**
  - Internalized knowledge
- **Explicit Knowledge**
  - Expressed knowledge
Knowledge is transformed through processes such as:
**Internalization → Tacit Knowledge → Externalization → Explicit Knowledge → Combination**
### (2) KDD Process
**KDD — Knowledge Discovery in Databases**
The KDD methodology consists of five stages:
1. **Data Selection**
2. **Data Preprocessing**
3. **Data Transformation**
4. **Data Mining**
5. **Interpretation / Evaluation of Data Mining Results**


---

## 5. CRISP-DM Analysis Methodology
### (1) Four-Level Structure of CRISP-DM
CRISP-DM has a four-level hierarchical structure:
1. **Phase**
2. **Generic Task**
3. **Specialized Task**
4. **Process Instance**
### (2) Six Phases of CRISP-DM
1. **Business Understanding**
2. **Data Understanding**
3. **Data Preparation**
4. **Modeling**
5. **Evaluation**
   - Evaluates the overall **modeling process**, not only the modeling phase itself.
6. **Deployment**


---

## 6. Big Data Analysis Methodology
### (1) Three-Level Structure
The Big Data Analysis Methodology consists of three hierarchical levels:
1. **Phase**
2. **Task**
3. **Step**
### (2) Five-Phase Process
1. **Analysis Planning**
   - Review
   - Decision
   - Complementation
   - Approval
2. **Data Preparation**
3. **Data Analysis**
4. **System Implementation**
5. **Evaluation and Deployment**


---

## 7. Top-Down Approach
### (1) Deriving Analysis Tasks
The approach depends on whether the direction of analysis is known.
- If the analysis direction is known:
  - **Optimization (OS)**
  - **Top-down**
- If the analysis direction is unknown:
  - **Insight Discovery (ID)**
  - **Bottom-up**
### (2) Top-Down Approach Process
1. **Problem Discovery**
   - Identify relevant use cases.
2. **Problem Definition**
3. **Solution Search**
4. **Feasibility Study**


---

## 8. Bottom-Up Approach
**Process Classification → Process Flow Analysis → Identification of Analysis Opportunities → Definition of Analysis Requirements**
### (1) Analysis Methodologies for Identifying Opportunities in Existing Bottom-Up Approaches
#### 1. Design Thinking Approach
- Repeatedly applies:
  - **Top-down**
  - **Bottom-up**
#### 2. Business Model-Based Approach
Analysis can be performed through:
- **Value Chain Analysis**
- **Value Analysis**
#### 3. Correlation and Association Analysis
Problems can be solved using:
- Correlation analysis
- Association analysis
The focus is on identifying relationships rather than necessarily proving causality.
### (2) Problem Solving Through Prototyping
Prototyping approach:
**Generate Hypothesis → Experiment with Design → Test in Real Environment → Derive Insights and Verify Hypothesis**
### (3) Defining Analysis Tasks
- Detailed algorithms do **not** need to be determined during the initial analysis-task definition stage.


---

## 9. Analysis Project Management
### (1) Management Areas of an Analysis Project
Important management areas include:
1. **Data Size**
2. **Data Complexity**
3. **Speed**
4. **Analytic Complexity**
5. **Accuracy & Precision**
### (2) Characteristics of Analysis Projects
Analysis projects require management techniques that combine:
- **Prototyping methods**
- **Agile project management**
### (3) Analysis Project Management Guidelines
- Based on the **KSA ISO 21500** standard guideline.


---

## 10. Establishing an Analysis Master Plan
### (1) Framework for Establishing an Analysis Master Plan
#### Factors for Prioritizing Analysis Tasks
Consider:
- **Strategic Importance**
- **Business Performance and ROI**
- **Ease of Implementation of the Analysis Task**
#### Factors for Determining the Scope and Method of Analysis
Consider:
- Scope of business application
- Scope of analytical data
- Scope of analytical technology
### (2) ISP — Information Strategy Planning
**Information Strategy Planning (ISP)** is the process of establishing a mid-to-long-term roadmap for strategically utilizing information technology or information systems within an organization.


---

## 11. Deriving Tasks and Evaluating Priorities
### (1) General IT Project Priority Evaluation Criteria
Task priorities are evaluated based on two major dimensions.
#### Strategic Importance
- **Strategic Necessity**
- **Urgency**
#### Implementation Feasibility
- **Investment Feasibility**
- **Technical Feasibility**
### (2) Analysis Task Priority Evaluation Criteria
When prioritizing analysis tasks while considering ROI, evaluate:
- **Urgency**
- **Difficulty**
### (3) Prioritization Through Portfolio Quadrant Analysis
Analysis tasks can be classified using two dimensions:
- **Difficulty**
- **Urgency**
| | High Urgency | Low Urgency |
|---|---|---|
| **High Difficulty** | Quadrant I | Quadrant II |
| **Low Difficulty** | Quadrant III | Quadrant IV |
The quadrant position helps determine the order in which analysis tasks should be performed.
### (4) Establishing an Implementation Plan
1. **Establish a Roadmap**
2. **Develop a Detailed Implementation Plan**


---

## 12. Establishing an Analytics Governance Framework
### Components of an Analytics Governance Framework
1. **Organization**
2. **Process**
3. **System**
4. **Data**
5. **Human Resources (HR)**


---

## 13. Analytics Maturity Model and Readiness Assessment
### (1) Six Areas of Analytics Readiness
1. **Analytics Activities**
2. **People and Organization**
3. **Analytics Techniques**
4. **Analytics Data**
5. **Analytics Culture**
6. **IT Infrastructure**
### (2) Analytics Maturity
#### Analytics Maturity Assessment Areas
- **Business**
- **Organization and Capabilities**
- **IT**
#### Four Levels of Analytics Maturity
1. **Introduction**
2. **Utilization**
3. **Diffusion**
4. **Optimization**
### (3) Analytics Maturity Assessment Results
Organizations can be evaluated according to both:
- **Maturity**
- **Readiness**
This produces four general categories:

| | High Readiness | Low Readiness |
|---|---|---|
| **High Maturity** | Expansion Type | Settlement Type |
| **Low Maturity** | Preparation Type | Introduction Type |
### (4) Establishing an Analytics Support Infrastructure Plan
Establish an infrastructure plan appropriate for the organization's analytics maturity and readiness.


---

## 14. Data Governance
### (1) Overview of Data Governance
Important concepts include:
- **Master Data**
- **Metadata**
- **Data Dictionary**
### Components of Data Governance
1. **Principles**
2. **Organization**
3. **Processes**
### (2) Establishing a Data Governance Framework
The basic process is:
**Data Standardization → Data Management Framework → Data Storage Management → Standardization Activities**
#### 1. Data Standardization
Establish common standards for organizational data.
#### 2. Data Management Framework
Define policies, roles, and procedures for managing data.
#### 3. Data Storage Management
Manage how data is stored and maintained.
#### 4. Standardization Activities
Continuously maintain and improve data standards.


---

## 15. Organizational Structure for Data Analytics
### (1) Organizational Structures for Data Analytics
Three major organizational structures can be used:
1. **Centralized Organizational Structure**
2. **Functional Organizational Structure**
3. **Distributed Organizational Structure**
### (2) Analytics Task Management Process
#### 1. Task Identification
**Generate Task Ideas → Propose Candidate Analysis Tasks → Confirm Analysis Tasks**
#### 2. Task Execution and Monitoring
**Build Team → Execute Analysis Task → Manage Analysis Task Progress → Share Results / Improve**
### (3) Analytics Education and Change Management
Organizations should support:
- Analytics education
- Organizational change management
- Development of analytical capabilities
